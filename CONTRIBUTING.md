# Contribuir

Obrigado por ajudar a melhorar a edição Codex.

## Reportar problemas

Abra uma issue com o objetivo, sistema operacional, versões de Python/Node/Codex, passos de reprodução e resultado esperado/observado. Remova caminhos privados, tokens e conteúdo de clientes dos exemplos.

## Propor mudanças

1. Faça um fork e crie uma branch para uma mudança delimitada.
2. Preserve a atribuição original e a licença MIT.
3. Mantenha alinhados `codex/prompts/` e `codex/skills/vibe-codex/references/` quando alterar um fluxo.
4. Não altere silenciosamente os assets ESLint upstream; documente a origem e atualize hashes apenas quando houver mudança deliberada e revisada.
5. Rode os comandos de verificação do README e descreva resultados e limitações no pull request.

A documentação deve distinguir recursos do Codex, convenções deste toolkit e capacidades opcionais. Não apresentar orientações em Markdown como controles executáveis, nem prometer instalação de ferramentas que não são distribuídas aqui.

Não adicione dependência ou instalador global para uma mudança apenas documental. O instalador deve continuar preservando arquivos existentes e oferecendo prévia sem escrita.
